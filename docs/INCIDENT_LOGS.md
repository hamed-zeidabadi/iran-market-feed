# آرشیو خطاها و قیمت‌های مشکوک

## محل نگهداری

لاگ هر اجرا JSONL است؛ هر خط یک رکورد مستقل با زمان UTC (`at`)، ساعت تهران (`at_tehran`)، شناسه و نوبت اجرای Actions، لینک اجرا، commit، fingerprint تنظیمات و نوع محیط اجرا. نسخهٔ محلی کنار فایل state و خارج از `public` ساخته می‌شود. بدنهٔ پاسخ، هدرها و رمزها ثبت نمی‌شوند؛ hash بدنه برای تشخیص تغییر پاسخ موجود است. مقدار قیمت‌ها برای بررسی خطا در لاگ خصوصی می‌آید.

آرشیو اصلی، Worker مستقل `iran-market-feed-audit` با سه دیتابیس خصوصی D1 است. فایل‌های اجرا به‌صورت فشرده ذخیره و بر اساس ماه بین سه بخش تقسیم می‌شوند. حذف رکوردهای بیش از **۲۱۰ روز** هر روز انجام می‌شود؛ state عملیاتی آخرین اجرا جداگانه حفظ می‌شود. نزدیک شدن هر بخش به ۳۵۰ مگابایت، رخداد `archive_storage_pressure` ایجاد می‌کند. Worker زمان‌بندی و پروکسی تتر تغییر نکرده‌اند.

`AUDIT_URL` و `AUDIT_SECRET` در Secrets مخزن و رمز متناظر در Worker تنظیم می‌شوند. هیچ endpoint خواندن/نوشتن بدون رمز در دسترس نیست. شناسهٔ دیتابیس رمز نیست. دادهٔ آرشیو با قیمت مرجع ترکیب نمی‌شود و هیچ وزنی یا آستانهٔ پذیرش تغییر نکرده است.

## چه چیزهایی ثبت می‌شود؟

| رخداد | معنی و شواهد |
|---|---|
| `transport_failed` | هر تلاش ناموفق، حتی اگر تلاش بعدی موفق شود؛ 403، 429، 5xx، timeout، مشکل DNS/TLS و مسیر direct/proxy/WebSocket |
| `source_recovered_after_retry` | شکست اولیه با تلاش بعدی یا پروکسی بازیابی شد |
| `source_result` | نتیجهٔ هر منبع، تعداد نرخ‌ها، HTTP، نوع خطا، تعداد تلاش و مدت دریافت؛ اجراهای موفق نیز برای محاسبهٔ درصد خرابی ثبت می‌شوند |
| `slow_source` | دریافت منبع حداقل ۱۰ ثانیه طول کشید؛ فقط هشدار عملکردی |
| `asset_missing` | منبع پاسخ قابل استخراج داشت اما یکی از دارایی‌های پیکربندی‌شده را نداد |
| `quote_observation` | قیمت، واحد، عیار، نوع نرخ، زمان اعلام/snapshot، دلیل رد و مشارکت در مرجع برای هر قلم تحت پوشش |
| `quote_rejected` | دادهٔ قدیمی، زمان نامعلوم/آینده/نامعتبر، قیمت نامعتبر یا واحد/عیار ناسازگار |
| `snapshot_not_recent` | snapshot منبع قدیمی یا بیش از حد آینده است؛ snapshot با زمان اعلام واقعی یکی نیست |
| `price_outlier_candidate` | اختلاف بیش از سقف فعلی ۲٪ با میانهٔ حداقل دو گروه دیگرِ مرجع که خودشان در همان محدوده با هم توافق دارند؛ گروه خود منبع از مبنای مقایسه حذف می‌شود. نرخ‌های هم‌نوعِ دارای زمان تازه یا snapshot تازه قابل بررسی‌اند |
| `price_jump_candidate` | تغییر بیش از ۵٪ نسبت به نرخ قبلی همان منبع و دارایی با مبنای زمان یکسان؛ قیمت و زمان قبل/بعد ثبت می‌شوند |
| `frozen_price_candidate` | هشدار موجودِ ثبات مشکوک؛ فقط وقتی ساعت اعلام جلو رفته، هم‌زمان یک ناشر دیگر تغییر کرده و زمان کافی گذشته باشد |
| `reference_result` | وضعیت، تعداد گروه‌ها، بازهٔ قیمت‌ها، اختلاف و قدیمی‌ترین رأی هر مرجع. نبود رأی واجد شرایط برای اقلام مقایسه‌ای با severity=info ثبت می‌شود |
| `collection_failed` / `collection_incomplete` | اجرا استثنا داد یا بدون رکورد پایان متوقف شد؛ فایل ناقص هم آرشیو می‌شود، اما state ناقص جای baseline معتبر را نمی‌گیرد |
| `publication_check_retry` / `publication_not_confirmed` | فایل مورد انتظار هنوز منتشر نشده، پاسخ نامعتبر یا خطای دریافت وجود دارد |
| `publication_delayed` | بیش از ۵ دقیقه بین تولید گزارش و تأیید انتشار گذشته است |
| `workflow_finished` / `workflow_step_failed` | نتیجهٔ collect/deploy و نام job/step شکست‌خورده؛ حتی اگر تست یا collector پیش از ساخت قیمت شکست بخورد |
| `archive_upload_failed` / `archive_state_restore_failed` | خود ثبت/بازیابی آرشیو مشکل داشته است |

«نامزد قیمت پرت» یا «جهش» اثبات اشتباه بودن قیمت نیست؛ نوسان واقعی و اختلاف بازار هم ممکن است. این‌ها **صرفاً شواهد برای بررسی** هستند و به حذف نرخ یا تغییر میانه منجر نمی‌شوند. ثابت ماندن قیمت در طول روز به‌تنهایی ایراد تلقی نمی‌شود. `last_trade` صرافی با مرجع midpoint مقایسهٔ هم‌نوع فرض نمی‌شود.

## اگر Actions اصلاً اجرا نشود

Worker مستقل هر **۱۰ دقیقه** نشانی عمومی فید را می‌خواند و heartbeat ماندگار می‌نویسد. سن خروجی بیش از ۲۰ دقیقه، زمان آینده، پاسخ نامعتبر/قطع دسترسی و وقفهٔ دریافت لاگ collector بیش از ۲۰ دقیقه ثبت می‌شود. بنابراین نبودن خود Actions هم قابل مشاهده است. API عمومی GitHub از IP Cloudflare در آزمایش 403 داد؛ وابستگی اجباری به آن وجود ندارد. جزئیات jobهای شکست‌خورده توسط job مستقل Actions با توکن کوتاه‌عمر همان اجرا و دسترسی `actions:read` ثبت می‌شود.

اگر خود Worker آرشیو هم قطع باشد، فاصلهٔ heartbeatها پس از بازگشت در گزارش خروجی دیده می‌شود؛ بازهٔ بدون رکورد به معنی «سالم بودن» نیست. خطای آرشیو باعث قطع انتشار قیمت نمی‌شود و نسخهٔ بازیابی JSONL در artifactهای Actions تا ۹۰ روز می‌ماند. شکست job مستقل آرشیو در وضعیت workflow هم دیده می‌شود. این artifactها تابع دسترسی مخزن GitHub هستند؛ آرشیو خصوصی D1 منبع اصلیِ نگهداری ۲۱۰روزه است.

## شش ماه بعد چطور بخوانیم؟

در GitHub وارد **Actions → Export incident history → Run workflow** شوید:

1. `from_date` و `to_date`: تاریخ میلادی UTC، مثل `2026-11-12` تا `2027-05-12`؛ روز پایان شامل می‌شود.
2. `source_id`: برای همهٔ منابع خالی بگذارید؛ مثلاً `ramzinex_usdt` برای فقط رمزینکس.
3. `issues_only`: به‌صورت پیش‌فرض فعال است و فقط هشدار/خطاها را در فایل می‌آورد. برای همهٔ رکوردها خاموش کنید.
4. artifact با نام `incident-history` را دانلود کنید. فایل `incidents.jsonl.gz` لاگ است و فایل summary کنار آن، تعداد رخدادها، نمونه‌ها/خرابی هر منبع و وقفه‌های بیش از ۲۰ دقیقه را دارد.

در صورت اجرای محلی با Secret در محیط، نه در خط فرمان:

```powershell
python -m scripts.export_incidents --from 2026-11-12 --to 2027-05-12 --issues-only
```

خروجی پیش‌فرض در `.validation/export/` است. export صفحه‌بندی و محدود به سقفِ رکوردهای موجود در لحظهٔ شروع است؛ اضافه شدن اجرای تازه، رکوردی را در همان export جا نمی‌اندازد. بازپخش فایل‌های بازیابیِ قدیمی نیز زمان اصلی رخداد را حفظ می‌کند. بازهٔ تاریخ بر اساس زمان شروع batch است؛ هر خط زمان دقیق خودش را دارد.

این سامانه ثبت و گزارش می‌کند؛ پیام‌رسانی یا اعلان بیرونی فعال نشده است. برای مشکل تازه لازم نیست شش ماه صبر کرد؛ هر زمان می‌توان گزارش بازهٔ کوتاه گرفت.
